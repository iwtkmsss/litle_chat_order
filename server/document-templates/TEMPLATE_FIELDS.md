# Інструкція для підготовки docx-шаблонів

Ця директорія містить робочі копії шаблонів, які сервер може заповнювати через `docxtemplater`.

## 1. Загальна інструкція

Редагувати потрібно тільки робочі копії:

- `appendix3.template.docx`
- `appendix4.template.docx`
- `appendix5.template.docx`

Не редагуйте офіційні зразки у `client/public/documents`. Вони залишаються джерелом для перегляду і резервного копіювання.

Плейсхолдери вставляються у форматі `{fieldName}`. Один плейсхолдер має бути цілісним текстом: не розбивайте його стилями, переносами, таблицями або пробілами. Не вставляйте плейсхолдер частинами, наприклад `{customer + Name}`.

Після збереження `.docx` запустіть перевірку:

```bash
npm run check:template-placeholders -w server
npm run check:template-generation -w server
```

## 2. Як вставляти плейсхолдери

1. Відкрийте потрібний `.template.docx` у Word або LibreOffice.
2. Знайдіть підкреслене місце, порожнє поле або місце, де має бути значення.
3. Замініть порожнє місце або допишіть відповідний плейсхолдер, наприклад `{customerName}`.
4. Збережіть файл саме у форматі `.docx`.
5. Не змінюйте юридичний текст документа, якщо це не окреме погоджене завдання.

## 3. Якщо поле повторюється

Один і той самий плейсхолдер можна використовувати кілька разів. Наприклад, `{customerName}` може бути в реквізитах, у підписі і в іншому місці документа. Система підставить одне й те саме значення в усі місця.

## 4. Поля так/ні

Для полів типу `{thirdPartyConnection}` система вже передає готовий текст `так` або `ні`. У шаблоні достатньо вставити сам плейсхолдер у потрібне місце.

## 5. Відсутні дані

Якщо значення не заповнене в заявці, система підставить порожній рядок. `undefined`, `null`, сирі об’єкти або `true/false` у документ не потрапляють.

## Додаток 3. Заява на приєднання

| Плейсхолдер | Що означає | Де вставити у шаблоні | Обов’язковість | Коментар |
| --- | --- | --- | --- | --- |
| `{operatorName}` | Найменування Оператора | У зверненні або реквізитах Оператора | Так | Береться зі станції/компанії або даних заяви |
| `{customerName}` | ПІБ або найменування заявника | У полі “від” / реквізитах заявника | Так | Основний заявник |
| `{mailingAddress}` | Адреса для листування | У блоці адреси заявника | Так | Якщо не заповнено, буде порожньо |
| `{customerEmail}` | Електронна адреса заявника | У контактах заявника | Так | Використовується замість SMS-комунікації |
| `{customerPhone}` | Телефон заявника | У контактах заявника | Так | Контактний телефон |
| `{objectName}` | Найменування об’єкта | У тексті заяви про об’єкт | Так | Якщо немає назви, fallback бере адресу |
| `{objectAddress}` | Адреса об’єкта | У тексті заяви про місцезнаходження об’єкта | Так | Основна адреса приєднання |
| `{connectionReason}` | Причина звернення | У полі причини/підстави приєднання | За наявності | Наприклад нове приєднання |
| `{representativeName}` | Представник замовника | У блоці представника | За наявності | Якщо представника немає, буде порожньо |
| `{representativePhone}` | Телефон представника | У контактах представника | За наявності | Не дублюйте з телефоном заявника без потреби |
| `{representativeEmail}` | Email представника | У контактах представника | За наявності | Для листування з представником |
| `{statementDate}` | Дата подання заяви | Біля дати заяви | Так | Береться з дати реєстрації/отримання |
| `{signerName}` | ПІБ для підпису | У блоці підпису | Так | Заявник або представник |
